# Adyatithi Panchaanga

**https://adyatithi.github.io/panchaanga/**

A static web app that presents the Adyatithi daily pañchāṅga: the same computation and the
same content as the PDFs, arranged for a phone. There is no build step and no server. The
folder is the site.

## Views

| Tab | What it shows |
|---|---|
| दिनम् (Dina) | The simplified day: the PDF's two-panel head, sun and moon, the five angas with what follows each, observances, and the kaalas to keep clear of. When the page is today's, a strip shows what is running now. |
| कालाः (Kaala) | The day drawn to scale from the brāhma muhūrta to the next sunrise: divisions of the day, sandhyā windows, rāhu/yama/gulika, durmuhūrta, tyājya and amṛta kāla, with each anga's change marked and "now" as a line. The same in list form below, then the lagnas. |
| विस्तरः (Vistara) | Everything the PDF page prints, in its order, then the hyperlinked edition's detail: sandhyāvandana and śrāddha kālas, horās, tārābala, muhūrtas, the anga ślokas and devatās, what to avoid, and the festival notes. |
| मासः (Maasa) | A month grid with the moon's phase, solar day and nakshatra per cell, and the month's observances listed below. |
| पञ्चाङ्ग-पठनम् (Pathanam) | Reached from Dina. The day set for reading aloud: each anga with its śloka and devatā in large type, then the nishiddha lines. |
| पर्वाणि (Parva) | The year's lists from the PDF front matter (ekādaśī, pradoṣa, saṅkramaṇa, eclipses, anadhyayana …), the nava-nāyakas, the ūna-śrāddha days, and search across every observance. |

Settings (city, script, clock, theme) and the About page are behind the icon at the top right.
Labels are in Sanskrit, in the chosen script: Devanagari, Tamil, Grantha, Telugu, Kannada or Roman (ISO).

**Sharing.** The day page, the paṭhanam page and every observance have a प्रेषणम् button: an image
drawn in the browser from the same data, the day as text (for WhatsApp and the like), or the link.

**Offline.** After the first visit the whole Kali year for the chosen city, and the text for the
chosen script, are fetched in the background and kept.

Every day has an address: `#/Chennai/2026-05-19`, `#/Chennai/2026-05-19/kala`, and so on.
Swipe, or use the arrow keys, to change the day.

## Run it locally

```bash
python3 -m http.server 8000 --directory app
```

Then open http://localhost:8000/. (Opening `index.html` from disk does not work: browsers do
not load JavaScript modules or JSON from `file://`.)

## Publish

These files sit at the root of `adyatithi/panchaanga`, with GitHub Pages set to deploy from the
default branch (Settings → Pages → Deploy from a branch → `main`, `/ (root)`). All paths are
relative, so the app works under any path. `.nojekyll` is present so that Pages serves the
files as they are. After changing any file under `js/` or `css/`, raise `CACHE` in `sw.js` so
that installed copies pick the change up promptly.

## Data

`data/` is generated by the `adyatithi-panchaanga` Python package (the same code that produces
the PDFs), from its repository:

```bash
adyatithi generate app-data --years 5127,5128,5129
```

```bash
adyatithi generate app-data --years 5129 --cities Madurai,Coimbatore
```

Runs are additive: a second run adds cities and years to what is there and merges the shared
text dictionaries. A city-year takes roughly a minute. The writer is
`adyatithi_panchaanga/writer/panchaanga/app_json_writer.py`, whose docstring describes the file
layout and conventions. In short:

- times are integer minutes after local midnight of the page's date, truncated exactly as the
  PDF prints them, and keep counting past midnight (`1479` is `24:39*`);
- names are ids into `data/static/<script>.json`, which comes from the same tables the TeX
  writer reads;
- festival names, descriptions and nishiddha lines are stored once and shared by all cities.

In that repository, `pytest adyatithi_panchaanga/tests/test_app_data_matches_golden_tex.py`
re-renders every day's TeX lines from this JSON and compares them with the golden TeX of the
PDF pipeline. The app is developed there under `app/` and copied here.

## Layout

```
index.html            the shell
css/app.css           all styling; colours are tokens at the top, light and dark
js/app.js             settings, routing, the context each view renders from
js/data.js            loading of data/ (cached in memory; the service worker keeps it offline)
js/parts.js           pieces shared by views: the head, sun/moon, anga lines, observances
js/view-*.js          one file per view
js/share.js           sharing: text, link, and the image drawn on a canvas
sw.js                 offline cache (stale-while-revalidate)
fonts/, icons/        typefaces (see fonts/README.md for licences) and the PDFs' icons
data/                 generated; do not edit by hand
```
